# /call в большой беседе звал только инициатора — реестр участников пуст

**Date:** 2026-06-11 18:05
**Files:** src/modules/summon/summon.service.ts, src/modules/bot/summon.update.ts, src/modules/bot/membership.update.ts, src/modules/chats/chats.service.ts, src/modules/i18n/messages.ts
**Severity:** high

## Problem

В большом групповом чате пользователь вызвал `/call`, и бот упомянул только
его самого вместо всех участников. Выглядело как «бот не работает», хотя
формально зов отработал (status=ok, notified=1).

## Root Cause

Telegram Bot API **не даёт списка участников чата** — бот узнаёт о людях
только из событий. В большом чате все три канала регистрации не покрывают
существующих участников:

1. `new_chat_members` Telegram не присылает для больших супергрупп (~200+),
   а для участников, вступивших до добавления бота, его не было вовсе.
2. Авто-регистрация по активности ловит только тех, кто **написал сообщение
   при боте**. В чате-«читалке» единственным написавшим оказался инициатор `/call`
   — его зарегистрировал activity-middleware прямо перед командой.
3. Миграция group → supergroup нигде не обрабатывалась: при апгрейде чата
   Telegram меняет chat id, и все записи `ChatMember` остаются под старым id —
   реестр нового чата начинается с нуля.

Итог: `listActiveSubscribed(chatId)` вернул одну запись — инициатора, и бот
«позвал» только его. При этом пользователю никто не объяснил, что реестр
неполный — тихая деградация выглядела как баг.

## Solution

1. **Миграция чата**: хендлеры `@On('migrate_to_chat_id')` /
   `@On('migrate_from_chat_id')` + `ChatsService.migrateChat(oldId, newId)` —
   транзакционно переносит чат на новый id (FK-связи следуют каскадом,
   onUpdate: Cascade — дефолт Prisma), удаляя авто-созданную «пустышку» под
   новым id, если activity-middleware успел её создать. Идемпотентно.
2. **Подкачка админов**: перед каждым зовом `SummonService.syncChatAdmins`
   получает `getChatAdministrators` и регистрирует не-ботов в реестре (не
   трогая подписку — `/leave` уважается). Это единственная категория
   участников, которую Bot API отдаёт явно.
3. **Честная обратная связь**: после успешного зова сравниваем `notified` с
   `getChatMembersCount - 1`; при покрытии < 90% бот отвечает сообщением
   `call_partial` («позвал N, ещё ~M не в списке — пусть напишут /join или
   любое сообщение»). Сбои обоих API-вызовов изолированы — зов не ломают.

## Prevention

- Любая функция, зависящая от собственного реестра (а не от API Telegram),
  должна **сообщать пользователю о неполноте данных**, а не тихо работать с
  тем, что есть.
- При проектировании ботов сразу обрабатывать `migrate_to_chat_id` — любой
  growing-чат рано или поздно станет супергруппой, и ключи по chat id
  «осиротеют».
- Помнить ограничение Bot API: списка участников нет; явно достать можно
  только админов (`getChatAdministrators`) и счётчик (`getChatMembersCount`).
- Тестировать сценарий «бот добавлен в старый большой чат», а не только
  «чат рос вместе с ботом».
