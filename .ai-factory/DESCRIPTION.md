# Зазывала — Telegram-бот созыва участников

## Обзор

Telegram-бот «Зазывала» на NestJS, который по команде созывает (тегает) всех участников группового чата одним сообщением с произвольным текстом. Так как Telegram не имеет нативного `@all`, бот ведёт собственный реестр участников (через opt-in/активность) и при зове упоминает их пачками, укладываясь в лимиты Telegram. Поддерживает помощников (со-ведущих с правом зова), кастомные подгруппы тегов, настройки на каждый чат и веб-админку для управления и аналитики.

Референс по поведению: семейство ботов @ZazyvalaTag2Bot / @ZazyvalaTag3Bot.

## Ключевые возможности

- **Зов всех** — одной командой упоминает всех зарегистрированных участников чата с прикреплённым текстом.
- **Реестр участников** — отслеживание входа/выхода, авто-регистрация по активности, подписка/отписка от зова (opt-in/opt-out).
- **Пакетные упоминания** — разбивка списка на батчи под лимиты Telegram (число упоминаний и длина сообщения), с задержками против rate limit.
- **Помощники (assistants)** — назначение пользователей, которым разрешено инициировать зов, с лимитом на чат.
- **Права и анти-спам** — кто может звать (админы / помощники / все), кулдауны между зовами, защита от флуда.
- **Кастомные группы тегов** — именованные подгруппы (команды/роли) и зов выборочного списка.
- **Настройки на чат** — текст зова по умолчанию, формат упоминаний, blacklist, язык (RU/EN).
- **Веб-админка** — дашборд: чаты, пользователи, статистика зовов, управление настройками и помощниками; аутентификация.

## Технологический стек

- **Язык программирования:** TypeScript (Node.js)
- **Фреймворк:** NestJS
- **Telegram:** nestjs-telegraf (обёртка Telegraf — декораторы `@Update`/`@Command`, DI, scenes)
- **База данных:** PostgreSQL
- **ORM:** Prisma (типобезопасный клиент + миграции)
- **Веб-админка:** REST/SSR на NestJS + отдельный фронтенд (определяется на этапе админки)
- **Конфигурация:** `@nestjs/config` + `.env`
- **Интеграции:** Telegram Bot API (long polling в dev / webhook в prod)

## Архитектурные заметки

- Модульная структура NestJS: отдельные модули `bot` (хендлеры Telegram), `chats`, `members`, `summon` (логика зова + батчинг), `assistants`, `settings`, `admin`.
- Доменная логика зова/прав отделена от слоя Telegram-хендлеров — хендлеры тонкие, бизнес-правила в сервисах.
- Доступ к данным изолирован через Prisma-репозитории/сервисы, чтобы доменные модули не зависели от ORM напрямую.
- Режим связи с Telegram переключается конфигом: long polling для разработки, webhook для продакшна.
- Подробный паттерн и границы модулей описываются в `.ai-factory/ARCHITECTURE.md`.

## Нефункциональные требования

- **Логирование:** структурированное, уровень через `LOG_LEVEL`; отдельная диагностика ошибок Telegram API.
- **Обработка ошибок:** устойчивость к 429/Flood control (ретраи с backoff), частичный успех зова не должен ронять процесс.
- **Производительность:** зов больших чатов (сотни+ участников) выполняется пачками асинхронно, не блокируя event loop.
- **Безопасность:** токен бота и `DATABASE_URL` только из окружения; проверка прав инициатора зова; защита эндпоинтов админки аутентификацией; rate limiting на зов.
- **Конфигурируемость:** поведение зова и лимиты настраиваются на чат и через переменные окружения.
