# Project Roadmap

> Telegram-бот «Зазывала» на NestJS: тегает (созывает) всех участников группы одним зовом с произвольным сообщением, с помощниками, настройками чата и веб-админкой.

## Milestones

- [x] **Каркас проекта и подключение бота** — Скелет NestJS, ConfigModule + `.env`, ESLint/Prettier, подключение к Telegram через `nestjs-telegraf` (long polling / webhook), команда `/start`, healthcheck.
- [x] **База данных и модели** — PostgreSQL + ORM (Prisma/TypeORM), схема: чаты, пользователи, участники чата, настройки чата; миграции и сидинг.
- [x] **Регистрация участников в группе** — Отслеживание входа/выхода, авто-регистрация по активности, подписка/отписка от зова (opt-in/opt-out).
- [x] **Зов всех (ядро)** — Команда тегания всех зарегистрированных участников, разбивка на батчи под лимиты Telegram, прикрепление произвольного текста к зову.
- [x] **Помощники (assistants)** — Назначение со-ведущих, которым разрешён зов; лимит на число помощников на чат.
- [x] **Права и анти-спам** — Кто может звать (админы / помощники / все), кулдауны между зовами, защита от флуда.
- [x] **Кастомные группы тегов** — Именованные подгруппы (команды/роли), зов выборочного списка участников.
- [ ] **Настройки чата и локализация** — Текст приветствия, формат упоминаний, blacklist, язык (RU/EN), команды настройки на чат.
- [ ] **Веб-админка** — Дашборд: список чатов, пользователи, статистика зовов, управление настройками и помощниками; аутентификация.
- [ ] **Наблюдаемость и надёжность** — Логирование, обработка ошибок Telegram API, метрики, graceful shutdown, ретраи.
- [x] **Деплой в Kubernetes** — Dockerfile (multi-stage), k8s-манифесты (Deployment, Service, Secret, опц. Postgres), CI (lint/build/test) + CD (build→ghcr→kubectl apply). Webhook-режим — позже при необходимости.
